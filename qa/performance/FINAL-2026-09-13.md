# ANT improvement and validation results

This completes the code fixes and automated validation undertaken in this review.
It does not establish commercial-product parity or certify every feature for
production. The review combined repository inventory, targeted source inspection,
automated tests, and an isolated Chromium smoke check.

## Changes delivered

- Preserve classic scripts and runtime assets in production web builds. The build
  gate checks asset existence, referenced script syntax, and a 15-second build budget.
- Fix the resume-review JavaScript syntax error that prevented the page's script
  from executing.
- Route application settings through Electron storage on desktop and JSON-backed
  localStorage in the browser, fixing uncaught web startup errors.
- Correct memory-cache TTL and capacity handling and use ordered LRU tracking.
  At 1,000 entries, local cache reads improved from 8.939 to 0.182 microseconds
  per lookup. This is a microbenchmark, not overall AI response speed.
- Restrict service-worker runtime caching to public assets, honor private/no-store
  responses, refresh from the network first, and preserve unrelated caches.
- Connect mobile job tracking, study-plan generation, and analytics to existing
  backend endpoints using the authenticated user's identity. Translate study
  sessions into visible steps and display the analytics fields the backend supplies.
  HTTP failures now reject instead of being treated as successful data.
- Repair native mocks and outdated service imports in mobile tests; wait for the
  login screen to mount. Correct stale backend async/session and debug-route tests.
- Remove the mandatory Mac-only Rollup package; retain it as an optional transitive
  dependency in the root lockfile. Include the previously ignored root lockfile
  required by `npm ci` and CI's dependency cache.
- Add desktop/mobile tests and production Chromium smoke checks to CI. Remote CI
  itself was not run in this workspace.

## Re-run

```sh
AINT_Venv/bin/python -m pytest backend/tests -q
npm --workspace ant-mobile test -- --runInBand --watchman=false
npm --workspace ai-note-taker test
npm --workspace ant-web test
npm run benchmark:web
npm run benchmark:browser
AINT_Venv/bin/python qa/performance/backend/cache-read.py
```

Use an isolated SQLite database for the backend suite. The successful full run
set `DATABASE_URL=sqlite+aiosqlite:////tmp/ant-final-backend-tests.db`,
`TESTING=true`, `USE_SQLITE=true`, `FORCE_SQLITE=true`, and `ANT_SKIP_ALEMBIC=1`.
Migration tests explicitly enable migrations on their own temporary databases.

Chromium must be installed with `node node_modules/playwright/cli.js install chromium`.
This session used `PLAYWRIGHT_BROWSERS_PATH=/tmp/ant-playwright-browsers` for both
installation and execution. Build before running the browser check.

## Limits still requiring product validation

- Live microphone/system audio, transcription accuracy, provider latency, and
  AI-output quality require representative recordings and configured providers.
- Native Android/iOS builds, packaged desktop installation, and full browser
  backend workflows were not verified. The 59 backend skips remain skips.
- Mobile notification scheduling is still a stub in the existing application.
  Passing its contract tests does not demonstrate native notification delivery.
- npm reported dependency advisories during environment repair; a dependency
  security audit and cross-platform clean installs were not completed here.
- Root lockfile validation was a dry run; it did not reinstall the entire tree
  or validate Linux/Windows native binaries.
