# Screen-aware interview assistance and compact conversation — October 4

Implemented:
- Desktop microphone and system-audio sockets request complete question events from the existing VAD/transcription route. The backend sends these without generating a competing answer or preview.
- Each question immediately captures fresh screen context, including when automatic screenshots are otherwise off. Stale attachments do not replace that capture.
- A serial queue waits for the current answer instead of cancelling it. Duplicate event IDs are ignored; changing/clearing chats invalidates queued questions. Responses use the existing conversation history; local vision now receives that history as well.
- Short task requests such as “Fix this error” and “Complete this function” pass question detection. Missing screen access is surfaced instead of pretending to see code.
- Typed Enter submits while listening continues. Repeated empty Enter during a pending answer does not start another recording.
- Conversation starts hidden; the first message reveals it automatically. Show/Hide controls remain available. Manual hiding during an existing chat does not delete messages or stop streams. Clearing the chat returns to compact mode.
- Native Electron reduces the window height, preserves expanded dimensions, and restores them (including maximized state). Compact dimensions are not saved as the normal window size.
- Exact greetings receive a short direct response without screen/resume analysis. Automatic local recovery prefers the installed Qwen 3.5 9B over the tiny vision model; explicit model choices are preserved.

Two fresh captures, no cancellation, automatic panel reveal and manual hiding verified. Observed first/follow-up answer times: 6.2s and 2.6s, not latency guarantees.
- Real Electron window test using the production resize handler: 960×720 → 960×240 → 960×720, message preserved.
