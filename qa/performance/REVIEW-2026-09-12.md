# ANT quality and benchmark review

Follow-up fixes and final automated results: [2026-09-13 report](FINAL-2026-09-13.md).

Scope: repository file inventory, architecture/documentation and build/test
configuration review, focused inspection of the production web build and backend
cache. This was a bounded review to conserve the requested token budget, not a
line-by-line review of every file or a certification of production readiness.
Existing uncommitted application changes were preserved.

## Changes and evidence

- Production web output previously omitted classic scripts while reporting a
  successful build. Preserve runtime assets without converting global scripts
  into modules. A repeatable CI check now verifies local HTML assets and PWA icons.
- Fixed unreadable entries without TTL, stale deadlines on overwrite, unbounded
  caches below ten entries, and needless eviction during updates at capacity.
  Cache reads no longer scan every expiration deadline.
- Web build: 0.599 seconds; 71 asset references checked; none missing.
- Cache tests: 39 passed. Existing Electron suite: 49 passed.
- Python syntax scan: 176 files parsed successfully; 394 application, test,
  configuration, and asset files inventoried across the main code directories.
- Restricted browser runtime caching to public static assets, bypassed
  authenticated requests, honored private/no-store responses, and changed to
  network-first refresh. Offline script failures return a network error instead
  of HTML. Activation deletes only ANT caches. Five regression tests passed.
- Fixed outdated synchronous invocations of async functions in session tests;
  all 13 session tests now pass.
- A second broad run excluding migration and on-disk recording checks reached
  1,040 passed, 59 skipped, and one failure. That failure was an outdated test
  expecting the deliberately removed public user-list debug endpoint. The test
  now protects its removal (HTTP 404); all 15 route-extraction tests passed on
  the targeted rerun. The entire broad suite was not repeated after that fix.
- Cache microbenchmark: about 49× faster reads at 1,000 entries. See the sibling
  benchmark documents for methodology and limits.

## Remaining validation

- Initial broad backend run stopped at five failures: 483 passed, 59 skipped.
  Two migration failures were traced to Alembic being absent from the local
  environment (already declared in requirements-test.txt). Two recording checks
  detect an existing debug recording; that data was not deleted. The async
  session-test failure was fixed and its suite rerun successfully.
- Browser flows, packaged desktop, and mobile tests were not run in this pass.
- Live microphone/system-audio capture, transcription accuracy, AI time to first
  token, and end-to-end response latency need representative audio and configured
  models/providers. No commercial-product parity claim is established here.
- Service worker behavior was verified with mocked worker events, not an actual
  browser offline session. Offline availability remains limited to cached assets.
- The generated build retains original runtime assets alongside Vite-transformed
  assets. Module migration and asset-size budgets remain future work.

Re-run: `npm run benchmark:web`, `npm --workspace ai-note-taker test`, and the
Python commands documented in `backend/cache-read.md`. Browser-cache regression
tests: `npm --workspace ant-web test`.

The second backend run used a temporary SQLite database and:
`python -m pytest backend/tests -q --tb=short --maxfail=5 --ignore=backend/tests/test_alembic_migrations.py --ignore=backend/tests/test_fix_33_no_stub_recordings.py`.
These exclusions were diagnostic only; neither was added to CI or pytest config.
